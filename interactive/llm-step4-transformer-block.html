Intuition-first LLMs · Step 4 of 11

Many heads, then the full Transformer block

In Step 3 the last "the" of "The king sat on the ___" used one attention pattern and had to squeeze two different questions — who sat? and sat on what? — into a single set of weights. Real models run several patterns in parallel (heads, each with its own Q, K, V), then wrap attention in feed-forward layers, residual "shortcuts" and normalization. Stack that block N times and you have the engine of an LLM.

Story so far ▸ X (embedding + position, Steps 1–2) went through one attention head (Step 3), which made the last "the" richer by blending in "king". This step ▸ running many heads at once and wrapping them into the full block you stack N times.
01Multi-Head Attention

Different heads, different jobs

The problem with one head. In Step 3 the last "the" gave king 43%, sat 22%, on 16%. That single set of weights is a compromise: it cannot be sharply on "king" (the subject) and sharply on "on" (what it attaches to) at the same time. The fix is not a bigger head but several small ones: the model learns several independent sets of Q/K/V projections. Each "head" looks at the same sentence differently, and — since nobody assigns jobs — they divide the labour on their own during training. Here are four heads on "The king sat on the", side by side, with hand-set patterns (except Head 1) to show the idea:

Each box is one head's attention matrix for the same five tokens: a row is a token asking, a column is a token being looked at, and the number is the percentage of attention (rows add to 100%; the dotted cells are the future, hidden by the causal mask). The outlined bottom row is the last "the", the one we need to predict from. Each head produces its own context vector for every token. The model concatenates all heads' outputs and passes them through one more linear layer (W_O) to mix them back together. This is the O — "writes back" — step from Step 3's Q asks · K offers · V delivers · O writes back: the mixed result is then added onto the token's residual stream just below.

Why this helps. Head 1 can find the subject while Head 2 tracks word order, Head 3 keeps a sentence-level summary and Head 4 hunts for the action — all at once, in a single layer. These four patterns are hand-designed illustrations: real heads show recurring behaviours, but their jobs overlap, vary with context and rarely fit one label. GPT-2 small uses 12 heads per layer; GPT-3 175B uses 96. More heads give more parallel attention patterns, though not automatically better quality.
02The Transformer Block

What wraps around attention

Attention alone isn't enough. A full block adds a feed-forward network (per-token thinking), residual connections (shortcuts that add the input back), and layer normalization (keeps numbers stable). Step through it:

Why add the input back? (residual) — live, on the last "the"

Attention's output for the last "the" is a blend of other tokens. If that replaced the vector, the token would forget what it was. The residual connection adds the output on top of the original: x + attention(x).

Why residual connections matter ▾

A residual connection computes output = layer(x) + x instead of just layer(x). The + x is a "highway": gradients can flow straight back through it during training, so even very deep stacks (GPT-3 has 96 blocks) keep learning. Without residuals, deep networks suffer vanishing gradients and barely train. It's arguably as important as attention itself.

What the feed-forward network does ▾

After attention mixes information between tokens, the FFN processes each token independently — two linear layers with a non-linearity (Linear → GELU → Linear, where GELU is just a smooth activation function that lets the network learn non-straight-line patterns), usually expanding to 4× the width and back. Intuition: attention gathers the relevant context, then the FFN "thinks about" what it gathered. It holds most of the model's parameters.

03Depth

Stack the block N times

The output of one block is the input to the next — same shape, so they chain cleanly. Early layers learn surface patterns (syntax, nearby words); deeper layers build abstract meaning. Slide to see how model size scales with depth:

Each block recomputes Q, K and V. Block 2 does not reuse block 1's Q, K, V: it multiplies its own input (block 1's output) by its own Wq, Wk, Wv. So a 12-block model has 12 sets of Q, K, V — which is why the KV cache in Step 7 stores a K and a V per layer for every token.

What is each weight matrix in a block learning?

A block has a handful of learned matrices. None is given a job by hand. Training (Step 5) pushes each one towards whatever lowers the loss, and these are the roles they tend to settle into:

WOHow to combine the heads and where to write the result back into the token's vector (the residual stream).merge the "who" head and the "previous word" head into one update.

Every block has its own copy of all of these, so a 32-block model has 32 different Wqs, 32 different Wvs, and so on. That is why blocks can specialise, which the next card shows.

Honest caveat: this is a simplified story based on probing studies (for example "BERT rediscovers the classical NLP pipeline") and "logit lens" experiments. Real layers mix jobs, the boundaries are blurry, and the same head can do different things in different contexts. The sentences under "our sentence" are an illustration, not measurements.

Two things people mix up. (1) Every layer outputs a vector for every token, because the next layer needs all of them as input — only at the very end is just the last token's vector used to predict the next word. (2) Attention moves information between tokens; the feed-forward network then transforms each token on its own — and much of what the model has learned is widely believed to live in those feed-forward weights.

Where this is heading

You now have the entire forward pass: tokens → embeddings + position → N transformer blocks → prediction head → next-token probabilities. But every weight started as random noise. How does it learn to produce good predictions? That's training — loss, gradients, and watching embeddings organise themselves out of pure noise. Step 5.
